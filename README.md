# AgriSage

**Smart Crop Disease Detection and Recommendation System**

AgriSage is a Flask web application that classifies uploaded crop-leaf photos with a bundled MobileNetV2 model and shows disease guidance. The interface supports **English, Hindi, and Marathi**.

> **Note:** This is an educational screening tool, not a definitive diagnosis. Image predictions can be wrong; confirm important treatment decisions with a qualified local agriculture professional.

## Features

- Leaf-photo classification using the included trained model and its matching label map.
- Crop Health Guide with local reference images and disease guidance.
- English, Hindi, and Marathi interface.
- Cached disease guidance with a built-in offline fallback; Gemini is optional.
- Flask route and prediction-flow tests.
- Render Blueprint for deployment.

## Run locally

Requirements: Python 3.11 or 3.12 and internet access for first-time package installation.

1. Open this folder in VS Code.
2. Run `bash run.sh` in the integrated terminal.
3. Open <http://127.0.0.1:5000>.

The first run creates `.venv`, installs dependencies, and creates `.env` from `.env.example`. Keep the terminal open while using the app; press `Ctrl+C` to stop it. Run `bash run.sh` again to start it later.

## Optional Gemini integration

Basic use does not require an API key. To enable Gemini-assisted guidance, add your key to `.env` as `GEMINI_API_KEY=...` and restart the app. Do not commit `.env` or publish API keys. The committed `.env.example` contains no secret.

## Tests

After dependencies have been installed, run:

```bash
.venv/bin/python -m unittest discover -s tests
```

## Deploy on Render

The `render.yaml` Blueprint configures a free Python web service. Connect this repository to Render and deploy the Blueprint. `SECRET_KEY` is generated by Render. `GEMINI_API_KEY` is optional; leave it unset if you do not need Gemini-assisted guidance.

Render's free service can sleep when idle and has an ephemeral filesystem. Local SQLite data and cached guidance can be lost on restart or redeploy; this setup does not promise permanent user data storage.

## Project layout

- `app.py` — Flask routes and prediction flow
- `research.py` — disease guidance and offline fallback
- `vision_verification.py` — optional image verification
- `models/` — active classifier and matching class labels
- `templates/`, `static/` — web interface and disease reference images
- `demo_images/` — small sample images for demonstrations
- `tests/` — automated tests
- `run.sh` — creates the local environment, installs dependencies, and launches the app
- `render.yaml` — Render deployment configuration

Raw training datasets, training experiments, temporary uploads, local databases, virtual environments, editor settings, and container-specific files are intentionally excluded. The trained model and matching label file are included because the application needs them to predict. Demo-image attribution is recorded in `demo_images/SOURCES.json`; gallery-image sources are recorded in `static/disease_images/SOURCES.md`.

## Model scope

The application uses `models/plantdisease_expanded_frozen_old_candidate.keras` with `models/labels_plantdisease_expanded_frozen_old_candidate.json`. Reference-gallery images illustrate disease appearance; they do not guarantee a correct prediction. Use the result as guidance, not as a substitute for field assessment.
